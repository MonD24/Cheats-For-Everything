<h1 align="center">Cheats For Everything</h1>

<p align="center">Укажите одиночную игру для ПК — харнес найдёт значения, проверит каждый чит в запущенной игре и соберёт трейнер. Работает локально на vision-модели в LM Studio.</p>

## Что получается

Для игр на Unity (Mono) — трейнер внутри игры: плагин BepInEx, оверлей со списком читов, горячие клавиши F1–F12.
Для остальных движков — отдельный `.exe`-трейнер, который подключается к игре.

У каждого чита в результате указано, как он проверен: в настоящем бою, измерением (высота прыжка,
пройденное расстояние, число на HUD) или чтением значения. Читы, не прошедшие проверку, отбрасываются.

Только одиночные игры. Игры с античитом (EasyAntiCheat, BattlEye, Vanguard, …) и только-онлайн игры
отклоняются. Перед любыми действиями папки сохранений копируются в бэкап.

## Что нужно

- Windows 10/11, Python 3.10+
- [LM Studio](https://lmstudio.ai) с vision-моделью. Проверено на `qwen/qwen3.6-35b-a3b` (рекомендуется,
  в основном работает из оперативной памяти), `qwen/qwen3.5-9b`, `google/gemma-4-12b-qat`.
- Установленная игра (библиотеки Steam, Epic и GOG находятся сами; подойдёт и любая папка)
- По желанию: Cheat Engine — для ручной работы с указателями и AOB

```
pip install -r requirements.txt
```

Unity-плагин собирается на лету компилятором C#, который есть в Windows
(`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`); .NET SDK не нужен.

## Как пользоваться

**Веб-интерфейс.** Запустите `start.bat`: он поднимет LM Studio, загрузит лучшую установленную модель и
откроет http://localhost:8765. Слева выберите игру (или вставьте путь к exe), в чате напишите, что нужно.
Справа — список читов, кнопка «Собрать .exe» собирает трейнер.

**Полностью автоматически, без интерфейса:**

```
python app/run_auto.py "D:\Games\SomeGame\SomeGame.exe"
```

Харнес сам установит нужное, запустит игру, пройдёт меню до геймплея, найдёт и проверит читы и сложит
результат в `games/<Игра>/`. С флагом `--no-vision` работает без модели (меню исследуются без чтения
экрана, проверки по HUD пропускаются).

**Результат** (в `games/<Игра>/`):

| Файл | Что это |
|---|---|
| `release/<Игра>Trainer.zip` | трейнер и README с клавишами и способом проверки каждого чита |
| `cheats.txt` / `trainer.json` | список читов (Unity-плагин / exe-трейнер) |
| `autopilot_report.json` | что пробовалось, найдено, оставлено и отброшено — с причинами |
| `playbook.json` | что харнес узнал об игре (маршрут по меню, класс игрока, значения); повторный запуск быстрее |

Собрать exe-трейнер вручную: `python build_trainer.py games/<Игра>/trainer.json`
(`--run-py` — запуск без сборки). Упаковать любой трейнер: `python -m trainerkit.package games/<Игра>`.

## Как это работает

```
выбор игры ─► определение движка ─► проверка античита ─► бэкап сохранений
                   │
       Unity Mono  │  всё остальное
     ┌─────────────┴──────────────┐
  плагин с рефлексией         маршрут через память
     │                            │
  меню ─► геймплей            меню ─► геймплей
  поиск значений опытами      числа с HUD ─► скан памяти
  хуки, необычные читы        цепочки указателей, проверка перезапуском
  проверка (значения, бой)    проверка по HUD
     └─────────────┬──────────────┘
           трейнер + отчёт
```

**Путь до геймплея.** Меню исследуются как граф точных состояний экрана. Vision-модель спрашивается
только на новых экранах: один скриншот и короткий список действий (подтвердить, назад, стрелки, пропустить
или клавиша из подсказки на экране). Действия, которые ничего не меняют или возвращают на уже виденный экран
(переключатель, «назад»), на этом экране запрещаются, поэтому исследователь не ходит по кругу. На страницах
настроек (число игроков, сложность) подтверждение лишь перелистывает значение, поэтому исследователь
спускается к нижней кнопке. Всплывающие окна закрываются клавишей из их подсказки. Маршрут сохраняется
парами «экран → действие» и повторяется по совпадению экранов: второй запуск доходит до геймплея примерно
за минуту.

**Unity: поиск значений опытами.** Плагин BepInEx (`unity/UniversalTrainer.cs`) принимает команды через
файловый канал. `snap`/`diff`/`find` работают как сканер памяти по всем числовым полям всех живых игровых
объектов, но с именами классов и полей. Кандидаты ранжируются по словам в именах (идентификаторы
разбиваются на слова) и по структуре (поле с соседом `Max…` — это полоска), затем проверяются: записать
значение, прочитать обратно и убедиться, что экран изменился вне маски шума, построенной по кадрам покоя.
Для денег харнес читает IL игры: метод, вызывающий установку надписи на HUD, показывает, какое поле
выводится и какой метод перерисовывает HUD (многие HUD обновляются только по игровым событиям). Затем
vision-модель читает число на HUD для подтверждения. God mode — хук Harmony (`CanGetHit → false`,
`TakeDamage → skip`) только для класса игрока. Игрок — тот объект, который двигается от клавиш движения.

**Необычные читы.** Переключатели разработчиков, оставленные в коде (невидимость, «неуловимость»,
бесконечная спецшкала), супер-прыжок и скорость (остаются, только если измеренная высота прыжка или
расстояние действительно растут), убийство с одного удара и заморозка врагов (класс врага — тот, у которого
то же поле здоровья, что у игрока), замедление и турбо.

**Проверка.** Каждый чит включается через плагин и проверяется. Здоровье и god mode проходят настоящий
бой: без чита игрок должен получать урон, с читом — нет. Проверки за собой убирают (деньги, добавленные во
время теста, списываются; модификаторы при выключении возвращают старое значение). Во время опытов игрока
бережёт страховка (хуки god mode); после «Игра окончена» исследователь возвращается в игру.

**Остальные движки: HUD как оракул.** Vision-модель читает числа на HUD (или открывает обычные клавиши
меню — инвентарь, персонаж, — если числа нет на HUD). Скан по диапазону находит это число в памяти; пока
оно меняется само, скан следует за направлением изменения; остальное сужается бисекцией записью: записать
особое число в половину кандидатов, спросить, показывает ли его HUD, вернуть как было. Сканер указателей
превращает адрес в куче в цепочки «модуль+смещение», игра перезапускается, и остаются только цепочки,
которые по-прежнему показывают число с HUD.

## Движки

| Движок | Маршрут | Состояние |
|---|---|---|
| Unity (Mono), в т. ч. новый Input System | плагин с рефлексией | полный конвейер; проверено на River City Girls, Pizza Possum |
| Unity (IL2CPP), Unreal, GameMaker, REDengine, свои движки | через память | значения, видимые числом на HUD или в меню |
| всё с античитом, только-онлайн игры | — | отклоняются |

Известные ограничения: полоски без чисел (здоровье во многих 3D-играх) маршрут через память пока не
находит; vision-модель иногда путает выделенный пункт меню (исследователь это обходит, но настройка может
измениться по дороге); для IL2CPP и Unreal пока нет плагина с рефлексией.

## Структура

| Путь | Что это |
|---|---|
| `app/run_auto.py` | полностью автоматический запуск |
| `app/server.py`, `app/static/` | веб-интерфейс |
| `app/agent.py`, `app/tools.py`, `app/unity_tools.py` | чат-агент на LM Studio и его инструменты |
| `trainerkit/autopilot.py` | конвейер Unity: меню, значения, хуки, необычные читы, проверка |
| `trainerkit/mem_autopilot.py`, `trainerkit/pointers.py` | маршрут через память и сканер указателей |
| `trainerkit/il_trace.py` | чтение IL: что выводится в надпись на HUD |
| `trainerkit/gamescan.py` | библиотека игр, определение движка и античита |
| `trainerkit/vision.py`, `trainerkit/screen.py`, `trainerkit/winshot.py`, `trainerkit/play.py` | вопросы к модели, сравнение кадров, снимок окна, ввод с клавиатуры |
| `trainerkit/runtime.py`, `build_trainer.py` | рантайм и сборка exe-трейнера |
| `unity/` | Unity-плагин, его сборка и установка, BepInEx 5 |
| `scanner.py` | сканер значений из командной строки |
| `tests/` | тесты без игры и GPU и две игры-заглушки |

## Настройки

| Переменная | По умолчанию | |
|---|---|---|
| `LMSTUDIO_URL` | `http://localhost:1234/v1` | сервер LM Studio |
| `TRAINER_MODEL` | лучшая установленная | принудительно выбрать модель |
| `TRAINER_GAME_VRAM_GB` | `3` | сколько видеопамяти оставить игре при загрузке модели |
| `TRAINER_REASONING` | `none` | `on` — чат-агент «думает» перед каждым шагом (намного медленнее) |
| `TRAINER_PORT` | `8765` | порт веб-интерфейса |
